# Business Rules — Unit 1: ERP Data MCP Server

## BR-01: Order ID Format

- Order IDs follow pattern `PO-YYYY-NNN` (e.g., PO-2026-001)
- Year component must be 4 digits
- Sequence component must be 3 digits, zero-padded
- Validation regex: `^PO-\d{4}-\d{3}$`

## BR-02: Plant Values

- Only two valid plant values: "Florida" and "Ohio"
- Case-sensitive string matching
- No other plant values accepted

## BR-03: Product Family Enumeration

- Valid product families: Steel Sheets, Steel Coils, Steel Plates, Steel Bars
- Each product family maps to specific machine requirements (see domain-entities.md)
- Each product family maps to a primary raw material

## BR-04: Priority Classification

- Valid priorities: P1, P2, P3, or null (unclassified)
- Only Florida orders receive priority classification
- Ohio orders retain null priority
- Priority can be updated multiple times (Planner reclassification)

## BR-05: Order Status Transitions

Valid transitions:
```
Active --> Delayed     (Ohio order delayed to free capacity)
Active --> Transferred (Florida order moved to Ohio)
Active --> Cancelled   (order cancelled)
Delayed --> Active     (delay reversed)
```

Invalid transitions (must return error):
- Transferred --> any (terminal state)
- Cancelled --> any (terminal state)
- Delayed --> Transferred (must reactivate first)
- Delayed --> Cancelled (must reactivate first)

## BR-06: Machine Capacity — Ohio Only

- Capacity data is only tracked for Ohio plant
- Florida plant is offline (disruption scenario)
- Queries for Florida capacity must return error with message: "Florida plant is offline"

## BR-07: Equipment Compatibility Matrix

| Product Family | Rolling Mill (Ohio) | Finishing Line (Ohio) |
|---------------|--------------------|-----------------------|
| Steel Sheets | Supported | Supported |
| Steel Coils | Supported | Not Required |
| Steel Plates | NOT Supported | Supported |
| Steel Bars | Supported | Supported |

- Steel Plates cannot be processed on Ohio Rolling Mill (equipment incompatibility)
- Steel Coils only require Rolling Mill (Finishing Line not needed)
- Equipment compatibility check is Layer 1 of the constraint funnel

## BR-08: Material-to-Product Mapping

| Product Family | Primary Material |
|---------------|-----------------|
| Steel Sheets | Hot-Rolled Coil |
| Steel Coils | Hot-Rolled Coil |
| Steel Plates | Steel Slab |
| Steel Bars | Steel Billet |

- Each product family consumes exactly one primary material type
- Material availability check uses this mapping to determine required material

## BR-09: Running Tracker Initialization

When a new session starts, the running tracker is initialized from current Ohio capacity:
- Rolling Mill hours = (total_hours - downtime) * (1 - utilization_pct/100) for each shift type
- Finishing Line hours = same formula
- Material surplus = available_surplus_tons from raw_materials table
- Manpower surplus = available_surplus from manpower table
- All order lists start empty

## BR-10: Running Tracker Update Rules

After each order decision:
- **Transfer approved**: Deduct order's machine hours and material tons from tracker; add order_id to orders_transferred
- **Delay approved**: Add freed capacity back to tracker; add order_id to orders_delayed
- **Rejected**: No capacity change; add order_id to orders_rejected
- Hour values cannot go below zero (error if attempted)
- Material values cannot go below zero (error if attempted)

## BR-11: Surplus Calculation Rules

- `available_surplus` = `total` - `committed`
- Surplus values are computed fields, not stored independently
- When queried, surplus is recalculated from current total and committed values
- Surplus can be zero but never negative in stored data

## BR-12: Customer ID Format

- Customer IDs follow pattern `CUST-NNNN` (e.g., CUST-1001)
- Validation regex: `^CUST-\d{4}$`
- Customer tier must be Tier1, Tier2, or Tier3

## BR-13: Date Format

- All dates use ISO 8601 format
- Due dates: `YYYY-MM-DD` (date only)
- Timestamps: `YYYY-MM-DDTHH:MM:SSZ` (UTC)
- Due date comparisons use date-only precision

## BR-14: Session ID Format

- Session IDs are UUID v4 strings
- Generated by Session Manager when workflow starts
- Used as partition key for running_tracker table
- One tracker per session (1:1 relationship)

## BR-15: Error Response Format

All MCP tool errors return consistent structure:
```json
{
  "error": {
    "code": "string",
    "message": "string"
  }
}
```

Error codes:
- `NOT_FOUND`: Resource does not exist (order, customer, session)
- `INVALID_INPUT`: Input validation failed (bad format, missing required field)
- `INVALID_TRANSITION`: Status transition not allowed
- `CONSTRAINT_VIOLATION`: Operation would violate a constraint (negative capacity)
- `INTERNAL_ERROR`: Unexpected server error

## BR-16: Concurrent Access

- MCP server is single-user (MVP constraint)
- No optimistic locking required
- Running tracker updates are sequential (one order decision at a time)
- DynamoDB conditional writes used for status transitions to prevent stale updates

## BR-17: Data Immutability Rules

- `order_id`, `plant`, `product_family`, `quantity`, `due_date`, `machine_types_required`, `customer_id`, `order_value`, `customer_tier` are immutable after creation
- Only `priority` and `status` can be updated on orders
- Machine capacity, manpower, and raw material base data are read-only (seed data)
- Running tracker is the only mutable state during a workflow session

## BR-18: Query Filtering

- `get_orders` with no status filter returns ALL orders for the plant (all statuses)
- `get_orders` with status filter returns only matching orders
- `get_materials` with no material_type returns all materials
- `get_customers` with no customer_id returns all customers
- Empty result sets return empty arrays, not errors

## BR-19: Setup Time Handling

- Setup time applies when switching between product families on a machine
- Setup time is per-transition (e.g., switching from Steel Sheets to Steel Bars)
- Setup time data is stored in `setup_time_by_family` map on machine_capacity
- Agents consume this data for scheduling calculations; MCP server only provides it
